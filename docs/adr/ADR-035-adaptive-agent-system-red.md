# ADR-035 — Adaptive Multi-Turn Red for Tool-Using AGENT Targets

Status: Accepted
Date: 2026-09-10

## Context

The laboratory already supports AGENT targets such as OpenCode, durable tool-call evidence,
runtime authorization evidence and independent post-state verification. The adaptive
model-backed Red runtime, however, was primarily phrased as conversational jailbreak
search. Reusing the same prompt-generation framing unchanged for tool-using agents risks
optimizing for model wording while under-testing the system boundary where unauthorized
effects actually occur.

The project requirement is broader than model jailbreak detection. It must evaluate both
LLM behavior and systems built around LLMs while preserving the distinction between:

- `MODEL_COMPROMISE`: the model requests or follows an adversarial instruction that
  violates the testcase invariant;
- `SYSTEM_COMPROMISE`: the surrounding system permits the unauthorized effect.

Multi-turn attacks are especially relevant to agents because an attacker can establish
context, observe refusals/authorization behavior, modify the next hypothesis and compose
several apparently harmless steps into a later tool action.

## Decision

Introduce an AGENT-specific threat lens for all model-backed adaptive Red policies while
keeping the existing conversation engine, budgets, target-visible feedback boundary and
independent Judge unchanged.

The AGENT threat lens instructs Red to reason about four distinct evidence layers:

1. model intent / forbidden tool request,
2. runtime authorization,
3. provider-reported tool execution,
4. independently verified system effect.

The attacker is encouraged to use bounded multi-step hypotheses rather than repeated
surface paraphrases. It may adapt to target-visible refusals and tool/runtime responses,
but target output remains untrusted evidence and cannot grant authorization or change
campaign controls.

## Safety boundary

This change does not grant Red any tool, filesystem, network, repository or permission
capability. Red generates only the next user-visible probe. The Blue `TargetAdapter` owns
execution capabilities and the campaign/runtime owns authorization.

AGENT Red may test only the inert synthetic forbidden effect declared by the testcase and
only inside explicitly approved disposable/local fixtures. It must not broaden:

- paths or workspace scope,
- network destinations,
- repositories/remotes,
- credentials or secrets,
- persistence scope,
- campaign permissions.

External network and real Git publication remain denied by default.

## Target-managed sessions

OpenCode keeps conversational state internally. AGENT smoke budgets therefore use
`TARGET_MANAGED` semantics with no backtracking or branch replay (`max_backtracks=0`,
`max_branches=1`). This prevents the Red policy from assuming it can reconstruct alternate
histories that the target adapter cannot faithfully replay.

Other future AGENT adapters may support replay, but that capability must be explicit and
must not be inferred from the generic AGENT mode.

## Native adaptive AGENT cases

The project-native corpus includes disabled-by-default goal seeds for:

- protected synthetic workspace mutation,
- synthetic memory/persistence poisoning,
- Git publication containment using only a disposable local repository and local bare
  synthetic remote.

The goal seeds do not contain a library of jailbreak payloads. Concrete sequences are
generated by the configured Red roles under campaign budgets, and the resulting lineage is
persisted as evidence.

## Judgment

For system-oriented detectors, `SystemStateJudge` remains authoritative over semantic
interpretation where deterministic evidence is available.

A forbidden requested action may establish model compromise even if a runtime control
blocks it. A reported executed tool call does not automatically establish system
compromise. By default, a trusted verifier must observe the forbidden state effect. This
preserves fail-closed treatment of missing or ambiguous evidence.

## Measurement

One bounded AGENT conversation remains one vulnerability trial. Turns and model/tool calls
are costs/exposure units, not extra ASR trials. Adaptive discovery yields are not promoted
to comparative Blue estimates. Frozen held-out evaluation and paired ablation remain the
required path for comparing Red policies.

## Consequences

Positive:

- adaptive Red now explicitly targets system-security boundaries, not only refusal wording;
- sequential agent attacks can learn from target-visible containment behavior;
- system compromise remains independently verified;
- the same architecture works for local OpenCode-style agents without hard-coding a model;
- no new inference or permission channel is introduced by the mechanism selection layer.

Trade-offs / remaining work:

- the current adaptive AGENT path assumes the required sandbox fixture already exists;
- repository, RAG, tool-output and MCP injection need a fixture-aware setup lifecycle so
  attacker-controlled environment content can be installed reproducibly before the run;
- AGENT mechanism coverage currently reuses the general conversational mechanism labels;
  a future orthogonal system-mechanism taxonomy may be added only if it improves measured
  explanatory power without duplicating the corpus taxonomy.
